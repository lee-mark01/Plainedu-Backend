## 1. 시작하기

| 용도 | 주소 |
|---|---|
| **Base URL** | `https://api.plainedu.org` |
| **Swagger UI** | https://api.plainedu.org/api-docs/ |
| Postman 임포트용 | `https://api.plainedu.org/api-docs.json` |
| 헬스체크 | `https://api.plainedu.org/api/health` |

- **`https` + 도메인 + 포트 없음.** Socket.IO도 같은 주소(`wss://`)
- EC2 IP 직접 접근 불가 — https 리다이렉트 + 인증서 불일치로 막힘
- Swagger 우측 상단 **Authorize**에 액세스 토큰 넣으면 🔒 API도 문서에서 바로 호출 가능 (새로고침해도 유지됨)

## 2. 인증 시스템

**소셜 로그인만 있음** (카카오 / 네이버 / 구글). 자체 회원가입·비밀번호 없음.

현재 앱처럼 Firebase 로그인을 이미 완료한 클라이언트는 인가 코드를 다시 교환하지 않고 아래 브리지를 사용한다.

```
Firebase user.getIdToken()
   ↓
POST /api/auth/firebase-token  { idToken }
   ↓
{ accessToken, refreshToken, user }
```

```
프론트에서 OAuth 인가코드(code) 획득
   ↓
POST /api/auth/{kakao|naver|google}  { code }   ← 네이버는 state도 함께
   ↓
{ accessToken, refreshToken, user }
```

| 항목 | 값 |
|---|---|
| 액세스 토큰 | **15분** · 헤더 `Authorization: Bearer {accessToken}` |
| 리프레시 토큰 | **7일**(미사용 시 만료) / **90일**(절대 만료) |
| 갱신 | `POST /api/auth/refresh` `{ refreshToken }` → 새 토큰 쌍 |

### 꼭 알아야 할 3가지

**① 신규 가입 여부가 body에 없다 — HTTP 상태코드로 온다**

| 코드 | 의미 | 이동 |
|---|---|---|
| `201` | 방금 가입한 신규 유저 | 온보딩 |
| `200` | 기존 유저 | 홈 |

**② 리프레시 토큰은 1회용 (rotation)**

갱신하면 이전 토큰은 즉시 폐기 → 응답으로 받은 **새 refreshToken으로 교체 저장 필수**.
이미 쓴 토큰을 다시 보내면 탈취로 간주해 **해당 기기 토큰 계보를 전부 삭제**하고 `401 TOKEN_REUSE_DETECTED` 반환.

> ⚠️ **갱신 요청이 동시에 여러 개 나가면 그대로 터진다.** (401 뜬 요청들이 한꺼번에 재시도하는 상황)
> **갱신은 1개만 돌리고 나머지는 대기시키는 큐**를 반드시 둘 것.

**③ 401은 code로 분기**

| code | 의미 | 처리 |
|---|---|---|
| `REFRESH_TOKEN_EXPIRED` | 리프레시 만료 | 재로그인 |
| `REFRESH_TOKEN_INVALID` | 없는/잘못된 토큰 | 재로그인 |
| `TOKEN_REUSE_DETECTED` | 재사용 감지 | 저장 토큰 전부 삭제 후 재로그인 |
| `PROVIDER_CONFLICT` (409) | 같은 이메일이 다른 소셜로 가입됨 | `message`에 제공자명 포함 → 그대로 안내 |
| `FIREBASE_TOKEN_INVALID` | Firebase ID 토큰이 잘못됐거나 폐기됨 | Firebase 재로그인 |

## 3. 온보딩 플로우

```
① 로그인            POST /api/auth/kakao               → 201이면 신규
                    (개인 가상계좌는 서버가 자동 생성)
   ↓
② 학교 선택         GET   /api/schools?keyword=연세     ← 검색
                    PATCH /api/users/me { school_id }   ← 선택        ⭐신규
   ↓
③ 대학 이메일 인증   POST /api/auth/email/send   { email }
                    POST /api/auth/email/verify { email, code }
   ↓
④ 팀 생성 / 가입     POST /api/teams ...                ← ②③ 둘 다 필요
```

- **개인 모드는 ①만으로 전부 사용 가능.** ②③은 팀 모드 진입할 때만 필요
- 진행 상태 판단 → `GET /api/users/me`의 `school: { id, name, is_verified }` (미선택이면 `null`)
- ②③ 없이 ④ 호출하면 **403** → 팀 탭 진입 시점에 미리 막는 게 좋음
- **학교를 다시 고르면 인증이 풀림** → ③ 재수행 필요

## 5. 공통 규격

전문은 [api-conventions.md](api-conventions.md).

```jsonc
// 성공
{ "success": true, "data": ... }

// 실패 — code는 없을 수도 있음. 분기는 code 우선, 없으면 status
{ "success": false, "message": "...", "code": "..." }
```

| status | 의미 |
|---|---|
| 400 | 입력값 오류 |
| 401 | 미인증·토큰 만료 |
| 403 | 권한 없음 / **선행조건 미충족**(학교 인증 등) |
| 404 | 없음 |
| 409 | 상태 충돌 (중복 등록, 이미 투표) |
| 429 | **요청 한도 초과** — `code: RATE_LIMITED` + `Retry-After` 헤더(초) |
| 500 | 서버 오류 — message 고정 문구, **파싱 금지** |

- 시간은 전부 **UTC ISO 8601** (`"2026-07-19T02:30:00.000Z"`) → 표시할 때 KST 변환
- **페이지네이션이 두 방식 섞여 있음:**

| 방식 | 요청 | 응답 | 사용처 |
|---|---|---|---|
| 페이지 번호 | `?page=&limit=` | `pagination: { page, limit, total }` | trading 주문내역 |
| 무한스크롤 | `?cursor=&limit=` | `hasNext` | community 피드 |
