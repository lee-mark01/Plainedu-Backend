## 1 서비스 정의

**한 문장 정의**
Plain edu는 시장을 읽고 잃지 않는 판단을 안전하게 반복 연습할 수 있는 금융교육 플랫폼이다.

**교육 철학 관점 N·비전**
Plain edu는 학교 금융교육(Plain School) 이후 학생의 학습을 이어가고, 교사와 학교가 성과를 확인할 수 있게 만드는 교육 운영의 디지털 레이어다.

**사업 관점 N·사업**
*   **문제 정의와 해결 구조**
    *   **문제의 본질:** 금융 지식 부족이 아니라 의사결정을 연습할 수 있는 도구와 환경의 부재 대부분은 실제 돈이 걸린 상황에서 처음 금융 의사결정을 경험한다.
    *   **학교 관점:** 외부 금융교육이 일회성 특강으로 끝나고, 학생 참여와 변화가 데이터로 남지 않는다.
    *   **해결:** 숏폼 퀴즈 모의투자의 반복 학습 사이클(개인)과 자산운용사식 팀 의사결정 시뮬레이션(팀)으로 판단을 연습시키고, 그 활동 데이터를 학교·교사에게 되돌려준다.

### 핵심 설계 원칙 (전 화면 공통)

| # | 원칙 | 구현 규칙 |
| :--- | :--- | :--- |
| 1 | 토스 UX 준수 | 입력 최소화(선택 우선)·한화면 = 한 질문 Primary CTA는 화면당 1개 |
| 2 | 행동 우선 | 사용자는 "가입했다"고 느끼기 전에 이미 한 번 행동한다 (첫 행동 고정) |
| 3 | 단일 계정, Scope 분리 | 개인 모의투자와 팀(동아리) 운용은 하나의 앱·하나의 계정, Personal / Group Scope로 분리 |
| 4 | 모바일 행동, 웹=관제 | 핵심 액션(주문·투표)은 모바일 전용. 웹은 확인·정리·관리만 담당 |
| 5 | 교육 목적 고지 | 모든 투자 관련 화면·콘텐츠에 "투자 권유가 아니며 교육·연습용" 고지 |

### 용어 정의

| 용어 | 정의 |
| :--- | :--- |

| 시즌 (Season) | 리그 운영 단위. 3개월(분기), 연 4회. 시즌별 점수 독립, 종료 시 계좌 초기화 |

### 문서 체계 (Document Hierarchy) v1.1 신설

PRD는 PM이 쓰는 "왜/무엇" 중심 상위 문서이고, 기능명세서(FRD)는 이를 엔지니어 디자이너 QA가 구현 가능한 수준으로 번역한 후속 문서다. 국제표준 ISO/IEC/IEEE 29148도 Stakeholder System Software Requirements 3단 구조를 규정한다.

| 단계 | 문서 성격 | Plain edu 대응 문서 | 상태 |
| :--- | :--- | :--- | :--- |
| Tier 1 - PRD | 왜/무엇, 사용자 중심, 성공지표 | 최종 사업 방향성, Plain edu 비전 | Notion 존재 |
| Tier 2 - 시스템 기능명세서 | 화면·기능 단위, 시스템 전체 커버리지 | 본 문서 | v1.1 |
| Tier 3 - 화면별 상세 명세 | 트리거·사전조건·예외케이스 인수조건(Given-When-Then) | 스프린트 착수 시 기능별 개별 작성 | 19장 샘플 4종 |

BABOK(IIBA) 4대 요구사항 분류 매핑: Business/Stakeholder Requirements는 1·3장, Solution Requirements (기능)는 4~13장, Solution Requirements(품질)는 14장, Transition Requirements(데이터 이관 등)는 별도 문서 미작성(17장 이슈 #15).
2026년 최신 동향은 AI 코딩 에이전트가 명세서를 직접 소비하는 Spec-Driven Development (GitHub Spec Kit 등, Spec → Plan → Tasks → Implement)다. Tier 3 문서를 코딩 에이전트가 읽는 실행 계약 형태로 확장하는 것을 중장기 과제로 남긴다.

## 4 온보딩·인증 (AUTH)
확정안(vFinal)과 Figma Login / Affiliation/team/ set up 섹션 기준. 화면 제작 완료 영역이다.

STEP 1: 로그인 회원가입 (휴대폰/카카오, 약관 동의)
STEP 2: 소속 선택·인증 (유형 → 학교/대학 검색 인증)
STEP 3: 팀 선택·인증 (기존 팀/새팀 만들기)
STEP 4: 역할 선택·완료 (Analyst/Trader → 첫 행동)

| ID | 기능 | 상세 | 규칙 |
| :--- | :--- | :--- | :--- |
| AUTH-01 | Splash | 로고 중앙 + "금융 의사결정을 연습하는 공간" | 1.5초 자동 전환 |
| AUTH-02 | Welcome | "처음 오셨군요, 어떤 분이신가요?" | CTA: [시작하기](Primary) / [이미 계정이 있어요](Text) |
| AUTH-03 | 대상 선택 | HS/UA/SEN 3분기 선택 (토스식 리스트) | "나중에 언제든 바꿀 수 있어요" 고정 노출. 정체성이 아닌 '여기서 할 일' 기준 문구 |

## 7 리그 시즌 시스템 (엔진)
리그는 단일 경쟁이 아니라 4개의 독립 랭킹 체계다. 개인 모드는 % 중심(실제 투자 성과), 팀 모드는 Point 중심(전략 포함 평가 점수)이다.

### 시즌 운영 규칙
| 규칙 | 값 |
| :--- | :--- |
| 시즌 길이 | 3개월(분기), 연 4회 |
| 점수 독립성 | 시즌별 완전 독립 |
| 계좌 | 시즌 종료 시 초기화 (V0 재지급) |
| 중도 합류 | 허용. 참여 가중치로 보정 |
| 참여 가중치 | 일 단위 반영 |

**참여 가중치 (ParticipationRatio)**
```text
SeasonDays = (SeasonEnd - SeasonStart) + 1
ActiveStart = max(JoinDate, SeasonStart)
ActiveEnd = min(LeaveDate or SeasonEnd, SeasonEnd)
ActiveDays = (ActiveEnd - ActiveStart) + 1
ParticipationRatio = ActiveDays / SeasonDays #소속 집계에만 사용
```

### 리그 4종 요약
| 리그 | 평가 대상 | 단위 | 계산식 | 가중치 |
| :--- | :--- | :--- | :--- | :--- |
| 개인 랭킹 | 개인 | % | (Vt-V0)/V0 x 100 | 없음 |
| 개인 소속 랭킹 | 소속(개인 집합) | % | Σ(개인점수 x 참여율) / Σ참여율 | ParticipationRatio |
| 팀 랭킹 | 팀 | Point | (R% x 0.9) + (Alignment x 0.1) | 없음 |
| 팀 소속 랭킹 | 소속(팀 집합) | Point | Σ(TeamScore x 참여율) / Σ참여율 | ParticipationRatio |

### 개인 점수
```text
PersonalReturn = (Vt - V0) / V0
PersonalScore = PersonalReturn x 100 (%)
```
* 단순 누적 수익률 (TWR 미사용), 수수료 0.03% 즉시 반영
* 정렬 기준: 1) PersonalScore 2) Participation Ratio 3) ActiveDays
* 계좌 0원: Score -100%, 거래 불가, 리그 참여 유지

### 팀 점수 (R% Alignment TeamScore)
팀 수익률과 전략 준수 점수·매주 금요일 정규장 종가 스냅샷, Active MP 기준
```text
R% = (Vt - V0) / V0 x 100
TotalValue = Σ(종가 x 수량) + Cash
CurrentWeight_i = (종가 x 수량) / TotalValue x 100
CurrentWeight_CASH = Cash / TotalValue x 100
Tolerance_i = TargetWeight_i x 0.02 #허용 오차 2%
RawDiff_i = |CurrentWeight_i - TargetWeight_i|
Diff_i = 0 (RawDiff_i <= Tolerance_i)
Diff_i = RawDiff_i - Tolerance_i (RawDiff_i > Tolerance_i)
TotalDiff = ΣDiff_i #목표 외 종목은 Target 0%로 계산
Alignment = 100 x (1 - TotalDiff / 200) #0~100 클램프
TeamScore = (R% x 0.9) + (Alignment x 0.1) #Point, 소수점 1자리
```

### 소속 집계 (가중 평균)
```text
OrgScore_individual = Σ(PersonalScore x ParticipationRatio) / Σ(ParticipationRatio)
OrgScore_team = Σ(TeamScore x ParticipationRatio) / Σ(ParticipationRatio)
```
* 단순 평균이 아닌 가중 평균. 분모 0이면 집계 제외
* 소속 랭킹은 대학/고등 분리 노출
